A01 — Broken Access Control

What is it?

Broken Access Control happens when users can act outside their intended permissions. For example: viewing another user's private data just by changing an ID in the URL.

This is the #1 OWASP vulnerability — attackers simply change a parameter like ?id=1 → ?id=2 and get someone else's data.

Vulnerable

You are logged in as Alice (id=1). Try fetching any user's profile by changing the ID.

Vulnerable Server Code

@app.route("/a01/vulnerable/profile")
def a01_vuln():
    uid = request.args.get("id", 1)
    # No check if requester owns this profile!
    user = db.execute(
        "SELECT * FROM users WHERE id=?", (uid,)
    ).fetchone()
    return jsonify(user)

Secure

Same request — but server checks that you only access your own profile.

Secure Server Code

@app.route("/a01/secure/profile")
def a01_secure():
    logged_in_as = 1  # from session in real app
    requested_id = int(request.args.get("id"))

    # Enforce ownership check
    if requested_id != logged_in_as:
        return jsonify({
            "error": "Access Denied"
        }), 403

    user = db.execute(
        "SELECT * FROM users WHERE id=?",
        (logged_in_as,)
    ).fetchone()
    return jsonify(user)

Key Takeaway

  • Never trust user-supplied IDs — always verify the request matches the logged-in user.
  • Use server-side sessions, not client-side values, to determine who is logged in.
  • Apply the principle of least privilege — users should only access what they own.
