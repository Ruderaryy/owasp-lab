A04 — Cryptographic Failures

What is it?

Cryptographic Failures happen when sensitive data is not properly protected — passwords stored in plaintext, weak hashing algorithms (MD5, SHA1), or sensitive data sent over HTTP instead of HTTPS.

If an attacker dumps your database and passwords are plaintext — every account is instantly compromised. With bcrypt, they get useless hashes that take years to crack.

Secure Code

#  Hash before storing
hashed = bcrypt.hashpw(
    password.encode(),
    bcrypt.gensalt()
)
db.execute(
  "INSERT INTO users VALUES (?,?)",
  (username, hashed)  # "$2b$12$..." in DB
)

#  Safe comparison
bcrypt.checkpw(
    password.encode(),
    stored_hash.encode()
)

Key Takeaway

  • Never store plaintext passwords — always hash with bcrypt, scrypt, or Argon2.
  • Never use MD5 or SHA1 for passwords — they are fast to crack. bcrypt is intentionally slow.
  • Use HTTPS — even hashed passwords can be stolen if sent over plain HTTP.
  • bcrypt includes a salt automatically — no two hashes are the same even for identical passwords.
