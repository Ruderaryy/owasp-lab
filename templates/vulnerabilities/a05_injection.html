A05 — Injection (SQL Injection)

What is it?

SQL Injection happens when user input is directly embedded into a SQL query. An attacker can type SQL code as their username/password and completely change what the query does — bypassing login, dumping tables, or deleting data.

It's been in the OWASP Top 10 for over a decade and is still one of the most exploited vulnerabilities on the web.

Normal query
SELECT * FROM users WHERE username='alice' AND password='pass123'
After injection: username = admin'--
SELECT * FROM users WHERE username='admin'--' AND password='anything' Everything after -- is a comment — password check is skipped!

Vulnerable

Try these attack payloads:

// result + executed query will show here

Vulnerable Code

#  String interpolation — NEVER do this
query = f"""
  SELECT * FROM users
  WHERE username='{username}'
  AND password='{password}'
"""
db.execute(query)
# attacker controls the query structure!

Secure

Same injections do nothing — input is treated as data, not SQL code.

// result will show here

Secure Code

#  Parameterized query
# The ? placeholders are filled SAFELY
# by the DB driver — input is always
# treated as plain data, never as SQL

db.execute(
  "SELECT * FROM users
   WHERE username=? AND password=?",
  (username, password)
)

💉 Common SQL Injection Payloads

Auth Bypass

admin'--

Comments out the password check entirely.

Always True

' OR '1'='1

Makes the WHERE clause always true — returns all rows.

Union Attack

' UNION SELECT * FROM users--

Appends a second query to dump another table.

Key Takeaway

  • Always use parameterized queries — never build SQL with string formatting.
  • ORMs (like SQLAlchemy) are parameterized by default — prefer them over raw SQL.
  • Validate and sanitize input — reject unexpected characters on the frontend AND backend.
  • Principle of least privilege — your DB user shouldn't have DROP or admin rights.
