A02 — Security Misconfiguration

What is it?

Security Misconfiguration happens when an app is set up insecurely — debug mode on in production, verbose error messages, default credentials, unnecessary features enabled.

A classic example: an attacker sends a bad request and gets back a full stack trace revealing your file paths, database names, framework versions, and internal logic. That's free recon.

Vulnerable

Try a valid ID (1–3), then try a non-numeric value like abc or a missing ID.

Vulnerable Server Code

@app.route("/a02/vulnerable/user")
def a02_vuln():
    uid = request.args.get("id")
    #  Crashes and leaks internal details
    user = db.execute(
        "SELECT * FROM users WHERE id=?",
        (int(uid),)   # throws ValueError if not a number
    ).fetchone()
    if not user:
        raise Exception(
            f"User {uid} not found. "
            f"DB: demo.db, Table: users"  #  internal info exposed
        )
    return jsonify(user)

Secure

Same bad inputs — server returns a clean generic error with no internal details.

Secure Server Code

@app.route("/a02/secure/user")
def a02_secure():
    uid = request.args.get("id")
    try:
        if not uid or not uid.isdigit():
            return jsonify({"error": "Invalid request."}), 400
        user = db.execute(
            "SELECT * FROM users WHERE id=?",
            (int(uid),)
        ).fetchone()
        if not user:
            return jsonify({"error": "User not found."}), 404
        return jsonify(user)
    except Exception:
        #  Log internally, never expose details
        return jsonify({
            "error": "Something went wrong."
        }), 500

Key Takeaway

  • Never run debug mode in production — Flask's debug mode exposes an interactive console.
  • Always return generic error messages to users — log the details server-side only.
  • Disable stack traces, directory listings, and verbose headers in production.
  • Remove default credentials, unused endpoints, and sample apps before deploying.
