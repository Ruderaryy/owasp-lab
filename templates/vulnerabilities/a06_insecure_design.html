A06 — Insecure Design

What is it?

Insecure Design means security was never considered during the design phase. Unlike misconfiguration (wrong settings) or injection (bad code), insecure design is a fundamental architectural flaw — the feature was built without security in mind at all.

A classic example: a login form with no rate limiting. An attacker can write a script to try thousands of passwords per second — a brute force attack — and the server happily responds to every single one.

Vulnerable Code

@app.route("/login", methods=["POST"])
def login():
    username = data.get("username")
    password = data.get("password")

    #  No rate limiting at all!
    # Attacker can try forever
    user = db.execute(
        "SELECT * FROM users
         WHERE username=? AND password=?",
        (username, password)
    ).fetchone()

    if user:
        return "Logged in!"
    return "Invalid credentials", 401

Secure — Rate Limited

After 5 failed attempts, the server locks you out for 60 seconds.

Secure Code

#  Track attempts per IP
login_attempts[ip] = [
    t for t in login_attempts[ip]
    if now - t < 60  # last 60 seconds
]

if len(login_attempts[ip]) >= 5:
    return jsonify({
        "error": "Too many attempts."
    }), 429  # HTTP 429 = Too Many Requests

login_attempts[ip].append(now)
# proceed with login check...

🏗️ More Insecure Design Examples

No Password Reset Limit

Allowing unlimited password reset emails lets attackers spam users or enumerate valid accounts.

Predictable IDs

Using sequential IDs like /order/1001, /order/1002 lets attackers enumerate all orders.

No CAPTCHA on Sensitive Forms

Signup and login forms without CAPTCHA are trivially automated by bots.

Key Takeaway

  • Think about security before writing code — threat model your features during design.
  • Add rate limiting to every sensitive endpoint — login, signup, password reset, OTP.
  • Use HTTP 429 (Too Many Requests) to signal rate limit responses.
  • Consider account lockout, CAPTCHA, and IP blocking as layered defenses.
