A03 — Software Supply Chain Failures

What is it?

Supply Chain attacks happen when malicious code sneaks in through a dependency — an npm package, a PyPI library, or a CDN script you didn't write but fully trust.

Real examples: event-stream (npm, 2018) — a popular package was taken over and malicious code was added to steal crypto wallets. SolarWinds (2020) — attackers pushed malicious updates to 18,000+ organizations via a trusted software vendor.

The scary part: your code is fine — the attack hides in code you import.

Real World Supply Chain Attacks

event-stream (2018)

npm package with 2M weekly downloads. Maintainer handed it to a stranger who injected code to steal Bitcoin wallets.

SolarWinds (2020)

Attackers compromised SolarWinds' build system. Malicious updates shipped to 18,000+ customers including US government agencies.

PyPI typosquatting

Packages named requeests, colourama — one typo installs malware instead of the real library.

Key Takeaway

  • Audit your dependencies — run pip audit or npm audit regularly.
  • Pin exact versions in requirements.txt — don't use open ranges like >=.
  • Check before you install — look at download counts, maintainer history, source code.
  • Use built-ins when a 3rd party package isn't truly needed.
  • Use hash verification — pip install --require-hashes.
